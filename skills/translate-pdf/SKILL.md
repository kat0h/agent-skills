# TeXのPDFを日本語に翻訳する（XeLaTeX）

元のPDFからフォントと位置データを含めてテキストを読み込み、ブロック（段落、コード、図、脚注など）に分割し、翻訳が必要な箇所のみを翻訳して、XeLaTeX でドキュメントを再構成する。ページ区切りは元のものとは一致しない。

## 組版（XeLaTeX）

blocks.json・訳文キャッシュ・クロップから、`lib/docgen.py` が doc.tex を書いてコンパイルする（`xelatex` を2回実行）。文書ごとのビルドスクリプト（`build_doc.py`）は `docgen` のAPI（`B.cmd`, `B.render`, `B.par`, `B.heading`, `B.code_block`, `B.crop_args` …）と訳文の参照 `docgen.Tr()`（`overrides.json` → キャッシュの順）だけを使い、呼び出すマクロを `template.tex` に定義する。

- 文書クラスは `extarticle`（9pt など）＋`geometry`、欧文 TeX Gyre Termes/Heros（Times/Helvetica 相当）、和文 原ノ味明朝/ゴシック（`xeCJK`、強調はゴシック）、コードは Latin Modern Mono（`fancyvrb` の `codeblock` 環境＝逐語）。
- 翻訳者が使う `―`（U+2015）や `…` は `\xeCJKDeclareCharClass{CJK}{"2015,…}` で和文扱いにしないと欧文フォントに無くて消える（log の `Missing character` を必ず見る）。
- マクロ名が既存と衝突しやすい（`\item` `\copyright` `\imath` → `listitem` `acmnotice` `inlinemath`）。
- 引数なしマクロの直後に和文が続くと制御綴の一部になるので `docgen` は `\name{}` を出す。
- 特殊文字は `{\char"XX}` でエスケープ（`B.esc`）。
- TeX Live が無ければ nix で入れる（`prepare.sh`）。tectonic は配布サーバーが 429 を返して使えないことがあるので使わない。

## 基本ルール（必ず守る）

- **入力PDFのあるフォルダには成果物以外を置かない。** 作業ディレクトリは既定で `${TMPDIR:-/tmp}/translate-tex-pdf/<stem>`。nix の GC ルートは `~/.cache/translate-tex-pdf/nix`。スクリプト・中間ファイル・PNG・ログはすべて作業ディレクトリへ。
- **出力ファイル名**：指示がなければ入力と同じフォルダの `<元の名前>_ja.pdf`（例：`paper.pdf` → `paper_ja.pdf`）。
- **原文にない文を足さない。** 成果物は個人用（private）なので、「機械翻訳である」旨の注記、モデル名、翻訳者注、フッターの注意書き、英語の原題の併記などは入れない。原文にある要素（タイトル、著者、所属、ランニングヘッド、ページ番号）だけを再現する。
- **出力PDFに英語本文を隠し持たせず、しかも軽く保つ。** 元PDFのページをそのまま切り抜いて埋め込むと、見えない英語テキストが残り（コピー・検索で英文が出る）、全ページをアウトライン化したPDFから切り抜くと全グリフがパスになって巨大化する（13ページ 0.6MB → 15.7MB）。そこで**クロップごとに専用の小さなPDF `crops/<key>.pdf` を作る**（`lib/crops.py`）：原文の該当ページから枠外を redaction で削除（`mutool run crops.js`）→ 残った少数の文字だけ `gs -dNoOutputFonts` でアウトライン化。座標は原文ページのまま。`docgen.crop_args` が登録し `docgen.write` が生成するので、文書ごとのコードは何もしなくてよい。結果は原文と同程度以下のサイズ（例：7.4MB → 1.1MB、15.7MB → 1.6MB）。`check.py` がクロップ内の文字・英文混入・サイズ膨張を検証する。
- 必要なコマンド，設定ファイルが現在の環境に存在しない場合，必要なものをユーザーにリクエストしてください．ユーザーの許可なく足りない道具をインストールしてはいけません．
    - nixでインストールできるものに関してはこの限りではありません．
    - 作業を開始してからの手戻りがなるべくおきないように，必要な道具が揃っているかは始めに検証するようにしてください．

## 構成

```
lib/                  共通部（文書に依存しない）。PYTHONPATH=$SKILL/lib
  prepare.sh IN.pdf [WORK] [OUT.pdf]  ツール確認/導入、env.sh、src.stext.xml、common.tex
  stext.py            mutool stext XML → pages→lines→spans、pages.pickle キャッシュ（load_pages）
  dump.py A B         ページA..Bの各行を「ベースライン x0-x1 | [フォント サイズ]テキスト」で表示。調査時は常にこれ
  layout.py           merge_lines（同一ベースライン統合・上下付き判定）、line_text、norm_text、tt_text、
                      collect_hyph_words / dehyphenate、ends_sentence、CITE + protect（引用の保護）、inline_crop
  translate.py        blocks.json → translations-<model>.jsonl（config.json：url / model / types / glossary / version）
  docgen.py           出力層：backend()、Tr（訳文の参照）、Content、cmd、render（⟦n⟧ / `code` / <i>）、esc、emph、code、code_block、
                      heading、par、footnote、crop_args（クロップを登録）、write（クロップ生成込み）、compile
  crops.py, crops.js  クロップごとのPDF：枠外を redaction で削除 → 残りの文字をアウトライン化（キャッシュ・並列）
  check.py OUT.pdf    検証：未翻訳なし、review 空、出力PDFに英語原文の断片なし、crops/*.pdf に文字なし、
                      サイズ ≤ max(3MB, 原文×4)、コードが doc.tex に逐語、描画時間（原文の3倍以下）
template/common.tex   \crop[s]{file}{x0}{y0}{x1}{y1} / \icrop[s]{file}{…}{base}（\def\PH{原文ページ高さ} を先に）
```

**文書ごとに書くもの**（作業ディレクトリに置く）：`extract.py`（余白・フォント分類・行分類・ブロック化）、`build_doc.py`（docgen を使う）、`template.tex`、`config.json`（サーバー URL・用語集）、`overrides.json`（手直し訳）、`build.sh`（extract → translate → build_doc → check）。文書に依存しない処理は `lib/` に足し、文書ごとのスクリプトに重複させない。

## 0. 準備と確認

```sh
$SKILL/lib/prepare.sh /path/to/paper.pdf   # WORK と OUT を表示する
cd $WORK && . ./env.sh                         # PATH, PYTHONPATH, SKILL, SRC_PDF, OUT_PDF
```

- `prepare.sh` は `mutool`、`gs`、XeLaTeX 一式（TeX Live：xeCJK・原ノ味・TeX Gyre）を確認し、無ければ nix で `~/.cache/translate-tex-pdf/nix` に入れる。**インストール済みと書かれていても鵜呑みにせず結果を見る。** nix が無ければユーザーにセットアップを依頼する。
- 翻訳サーバーを確認：`/v1/models`、および`/props`内の`chat_template`と`total_slots`。
  - APIキー（401 Invalid API Key のとき）：`translate.py` は環境変数 `PLAMO_API_KEY`、なければ `~/.config/plamo-api-key`（`PLAMO_API_KEY_FILE` で変更可）を読んで `Authorization: Bearer` で送る。`/props` もキーなしでは401。キーが無ければユーザーに求める。**キーを保存してはならない**（ファイルを作るのはユーザー）。
  - テンプレートが`chat_template_kwargs`を受け付ける場合は使用する（PLaMo 3 Translateは受け付ける）：`form: "plain"`（である調）、`source_lang: "en"`、`glossary: [{source, target}]`（テキスト中に語として現れる項だけ渡す）。
  - 並列リクエスト数（`--workers`）＝スロット数。
- 翻訳サーバーの URL を `config.json` の `url`（または環境変数 `PLAMO_URL`）に書き、短い文の翻訳で動くことを確認する。`model` はキャッシュのファイル名に使うラベル（モデルを替えたら変える）。URL が無いと `translate.py` は止まる。

## 1. 抽出：データからレイアウトを計測する

1. **コードを書く前に `dump.py` でページのジオメトリを計測すること。推測してはいけない。** 文書ごとに大きく違う：
   - 3imp（学位論文）：左余白が奇数/偶数ページで 108/72pt、テキスト幅 424.8pt、段落インデント +19.9、行間 21.5～22.7pt、本文 CMR。
   - Frontiers（論文）：A4、左余白 45.4/47.7pt、テキスト幅 502pt、インデント +8.5、行間 14.9pt、本文 NimbusRomNo9L（Times）、数式 CM*、左端に行番号（NimbusSanL 10pt, x1<42 → `merge_lines(keep=...)` で除去）、ランニングヘッド/フット（base<60, >780）。
   - 印刷ページ番号 = 物理ページ − オフセット（`pdftotext`で求める）。
   - ACM 2段組（Pycket）：Letter、列 x 54..294 / 317..557（幅240pt）、インデント +12、本文 Times 9pt・行間10pt、脚注 8pt、コード Inconsolata 8.1pt（1字 4.03pt）、項目の続き行は +13。
   - **2段組はまず列に分ける**（mutool の行 bbox の x0 < ページ中央で左列）。分けずに `merge_lines` すると左右の列の同じベースラインが1行に結合される。全幅の要素（タイトル・全幅図）はページごとに先に取り除く。
2. mutoolは均等割り付けで一つの視覚行を複数の行に分割する → `layout.merge_lines`（|Δbase| < 2pt を統合、小さいスパンは sup/sub）。
3. フォントカテゴリは文書ごとに `fcat` を書く（例：CMR/Nimbus = 本文、CMTI/Ital = 強調、CMTT = コード、CMMI/CMSY/CMEX = 数式、CMBX/Medi = 太字、図中フォント = X）。
4. 行の分類（順序が重要）：脚注開始 → 見出し → キャプション/Algorithm → リスト項目 → 本文 → それ以外は表示行。
   - 見出しは「余白から始まり番号で始まる太字（サンセリフ）行」**のみ**。数式内の太字は見出しではない。
   - 本文：x が余白またはインデントで、本文フォントが20%以上、図中フォント（X）を含まない。
5. 段落のルール：
   - **前の行が短く（x1 < 右端 − 15）、かつ本文フォントの文末記号で終わっている**場合に段落終了（`ends_sentence`）。行が短いだけでは終了ではない。
   - インデント位置の行は新段落。ただし前の行もインデント/項目位置で文末でなければ引用・項目の続き。
   - 別行数式の直後の余白行は `noindent` の新段落（原文では同一段落だが、数式で分割して訳す）。
   - 段落はページ区切りや浮動図版をまたいで続く（行を元の段落に足せば、図版は段落の後ろに出る）。
6. 表示行・浮動体のクロップ（すべて全テキスト幅、パディング 0）：
   - 図：前の要素のベースライン + 5pt（ページ先頭ならヘッダー下）からキャプションの y0 − 4pt まで。グリフの bbox ではなく範囲で切ると、テキストを含まない線画・写真も入る。
   - 表・アルゴリズム：見出し行の直後から、連続する表示行（間隔 < 26pt）の最後 + 5～7pt まで（罫線を含める）。アルゴリズムは見出し行の上の罫線（base − 15）から。
   - 別行数式：前行ベースライン + 5pt から次行ベースライン − 12pt まで（数式番号も入る）。
   - 全行 CMTT の表示 → `code` ブロック（インデントは (x − 余白)/文字幅 で復元）。
7. 行内数式（Times 本文 + CM 数式の論文）：CM スパンの連続を一つのプレースホルダにし、**原文から行内クロップ**（`layout.inline_crop`）してベースラインを合わせる（`icrop`、本文サイズ比で縮小）。太字ベクトルや花文字も正確に出る。
   - クロップは隣の本文スパンの手前で止める（`inline_crop` が自動でする）。止めないと隣の文字の欠片が縦線として写る。
   - 行末と次行頭にまたがる数式は一つの項目（複数ピース）にする。
   - `±` `×` のような単独記号はプレースホルダにせずテキストで渡す（モデルが落とす）。
8. 脚注：同一ページ内で番号を上付きマーカーに紐付ける。前ページの脚注が文末でない場合は、本ページ下部の間隔の狭い行グループを続きとする（3imp 例）。URL だけの脚注は翻訳しない。
9. ハイフネーション（`dehyphenate`）：行末の`-`は削除。ただしハイフン付きの形が行の途中にどこかで現れる場合、または次が大文字（GP-/HSMM）なら保持。
10. 行内の非テキスト要素：本文スパン間の異常に広い隙間（Pycket では > 9.5pt。ランイン見出しの後の空白は除外）は色付き凡例四角などの図形 → 隙間を行内クロップにする。
   - `\texttt` 内の `_` が罫線で描かれると mutool では空白になる（`jit merge point`）。行内コードの空白入りスパンを一覧し、文書ごとの置換表で直す。
   - TeX アクセント（`¨` `´`）が別スパンで x 順が後ろにずれることがある → 文字位置で対象文字の直前に戻してから `norm_text`。
   - 著者年引用にカンマが無い形式（`(Bolz et al. 2009; Bolz and Tratt 2013)`、`Hayashizaki et al. (2011)`）は文書ごとの正規表現で `protect`。名前に `\w`（ö など）を許す。
11. 正規化（`norm_text`）：合字はNFKC、`Gr¨ave` → `Gräve`（TeXアクセント）、全角括弧。コードでは`’` → `'`（`tt_text`）。
12. 前付・参考文献：
    - タイトルは翻訳ブロックにし、著者・所属は template.tex に手で書く（原文どおり英語）。要旨・謝辞は本文と同様。
    - 目次がある文書は `\tableofcontents`。
    - 参考文献：エントリに分割し英語のまま（型 `bib`。`check.py` の英文検出から除外される）。
13. 本文中の著者年引用 `(Argall et al., 2009; Lin et al., 2016)` は `protect(src, items, CITE)` でプレースホルダ化し、原文のまま出す。

## 2. インラインコンテンツの翻訳器への渡し方

- 純粋なCMTTのラン → `` `code` ``：文脈を与え、内容は逐語的にチェック。
- コード・数式・メタ変数・添字の混在ラン、行内数式クロップ、引用 → `⟦n⟧`。`items[n]` に元のスパン/クロップ/文字列を保持。コードラン内では `(` `[` `⟨` の深度 > 0 の間は吸収を続ける。
- 強調 → `<i>..</i>`。ただし **e.g. / i.e. / etc. にはタグを付けない**。単独のギリシャ文字はプレーンテキストでよい。
- 脚注参照 → `⟦n⟧`（kind fnref）。

## 3. 翻訳

### 3.1 頻出語彙を先に決める（ユーザーとのやり取りは最初に）

論文で何度も出る語を抽出し、その分野の日本語文献での慣用（著者グループの和文論文など）を調べて訳語を決める。分からないもの・方針が分かれるもの（例：segmentation → 分節化/セグメンテーション、アルゴリズム名を英語のまま残すか、分野固有の用語）は**抽出・翻訳の前に**まとめてユーザーに尋ねる。結果は `config.json` の `glossary` に書く。

### 3.2 翻訳の指示

- 温度0で、1段落につき1つのリクエスト。チェック：すべての`⟦n⟧`がちょうど1回出現、バッククォート内容の**集合**がソースと一致（出現回数の一致は求めない）。
- 失敗時：温度0.3と0.6で再試行 → コードもプレースホルダ`⟦cN⟧`にして再試行 → それでも失敗なら `review-<model>.txt` に記録。`<i>`タグのバランスが崩れたら全部削除。
- review に残ったもの・明らかな誤訳（例：名詞句のキャプションを文として訳す）は、原因を抽出側で直せるなら直し（単独記号など）、直せなければ `overrides.json`（src → 訳文）に手で書く。
- キャッシュキー = (version + 原文) のハッシュ。抽出を変えても原文が同じブロックは再翻訳されない。用語集を変えたら、影響する原文を含むエントリをキャッシュから消して再実行する。
- モデルごとにキャッシュを分ける（`MODEL` 環境変数か config）。実測：0.8B は 790 ブロック約 1.5 分、31B Q3 は約 1 時間、31B Q4（4スロット）は 74 ブロック約 3.5 分。

## 4. 出力の生成：落とし穴

- エスケープは `B.esc`（特殊文字を `{\char"XX}` に）。訳文・原文の文字列を直接 doc.tex に書かない。
- `<i>` のカウントは**随時**（`render` がする）。テキスト全体で数えると脚注などのネストで破綻する。
- PDFクロップ（`common.tex`）：`\crop` / `\icrop` は `crops/<key>.pdf` の1ページ目を原文ページ座標で切り抜く。先に `\def\PH{原文ページ高さ}` を定義する（Letter なら 792）。f文字列で自前に組む場合も `B.crop_args(page, bbox, ...)` を使う（登録されないとファイルが作られない）。
- 出力サイズ：上記のクロップ方式で原文と同程度以下になる。原文のページを丸ごと（またはアウトライン化した全ページを）埋め込んではいけない。redaction で `gs` が非準拠PDFの警告を出すことがある（ACM の著作権スタンプなど）が、出力は正常。
- **描画の重さ＝文字選択のもたつき。** ビューアは選択中にページを再描画するので、遅いページは選択が重く感じる。`mutool draw -q -stm -r 100 -o /dev/null -F ppm X.pdf` でページごとの描画時間を原文と比べる（`check.py` がする）。重いページは要素を外して二分探索する。犯人になりやすいのは、重なった・隠れた内容を含むクロップ（ACM の著作権スタンプは、白で隠した旧版の上に新版が重ねてある）や、アウトライン化した文字が密集した大きなクロップ。原文どおりの英語テキストで済むもの（著作権表示など）はクロップせず LaTeX で組む。
- 2段組：`twocolumn`。列上部の図は `figure`、全幅の図・タイトルは `figure*`。
- 図・表とキャプションは浮動体の中にまとめ、分離させない。
- 章ごとに脚注番号を戻す文書では章見出しのマクロで `\setcounter{footnote}{0}`。
- 見出しの訳は先頭を大文字化する（グロッサリーの小文字形がそのまま見出し頭に来る）。
- `xelatex` の log で `Missing character` と `Overfull \hbox` を確認する。

## 5. プロセス

1. `prepare.sh` → `dump.py` でレイアウト計測 → `extract.py` を書く（長い文書はまず1章分）。blocks.json を「型＋先頭文字」の一覧で出し、小文字始まりの段落・極端に短い段落・番号のない見出し・alt が長いクロップなどの異常を探す。
2. パイロット：翻訳 → ビルド → `mutool draw -r 70`（作業ディレクトリ内に PNG）で数ページを元と比較し、スタイルをユーザーと合意する。行内クロップは `-r 100` 以上で縁の欠片を確認する。
3. 長い文書では全章の抽出結果を**サブエージェント（sonnet）に読み取り専用でチェック**させる：見出しと目次の照合、リスト・引用の分割、脚注リンク、クロップ範囲。
4. 全文を翻訳・ビルド → サブエージェント（sonnet）に PNG を比較させる（図のクロップ端、分離したキャプション、空白ページ、ページ番号の重複、マークアップの露出）。
5. 大型モデルはバックグラウンドで実行。キャッシュが別なので並行してレイアウト修正を続けられる。

## 検証（`check.py "$OUT_PDF"` が OK を出すこと）
